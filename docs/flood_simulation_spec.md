# 潮位浸水シミュレーション仕様

作成日: 2026-08-26
対象: 舞鶴市・東舞鶴のハッカソン用プロトタイプ
ステータス: 実装仕様（MVP）

## 1. 目的

潮位と地盤高だけで計算する現在のモデルをベースラインとして残し、排水口と逆流防止施設の有無を仮想的に補った場合に、浸水範囲がどの程度変わるかを比較できるようにする。

このモデルは行政の正式な浸水想定を置き換えるものではない。実施設備データが未整備であることを前提に、次の2点を示すためのプロトタイプとする。

1. 潮位だけで説明できる浸水可能性
2. 排水施設の条件によって変化する浸水リスクと、今後取得すべきデータ

仮想データを使用した結果には、必ず「仮想モデルによる推定」「データ不足を補う仮定」「結果には不確実性がある」と表示する。

## 2. モデルの位置付け

既存のモデルを変更せず、比較用のモデルを追加する。

| モデル | 内容 | 用途 |
|---|---|---|
| `simple` | `max(0, H - E)` | 潮位以下の低地を広く把握するベースライン |
| `connected` | 海面と地表で連結したセルだけを対象 | 地形による浸水範囲を確認する |
| `drainage` | `connected` に吐口と陸側端のペア、およびゲート条件を加える | 排水口からの逆流条件を比較する |

ここで `H` は潮位 [m T.P.]、`E` は地盤高 [m T.P.] とする。

## 3. 適用範囲と前提

- 対象地域は既存の東舞鶴AOIとする。
- 地形は既存の0.5m DEMを基本とし、他の地形条件でも同じ計算を可能にする。
- 潮位は静水位または代表潮位として扱う。時系列の潮位変化、波浪、越波、堤防決壊、河川流量はMVPの対象外とする。
- 降雨による流入はMVPでは扱わず、必要になった場合は別シナリオとして追加する。
- 仮想排水網は、実在する施設の位置を示すものではない。
- 仮想排水口の位置・敷高・排水先・逆流防止施設の有無は、結果を一意に確定する実測値ではなく、仮定として扱う。
- **単調性を必須条件とする。** すべてのシナリオで、潮位 `H` を上げたときに浸水セルが減ってはならない。

## 4. 計算モデル

### 4.1 ベースライン

```text
depth_simple(c, H) = max(0, H - E(c))
```

既存の `simple` モデルをそのまま使用する。潮位0.9m、地盤高0.8mの場合は浸水深0.1mとなる。

### 4.2 地表連結モデル

既存の `h_conn` を使用する。

```text
wet_connected(c, H) = h_conn(c) <= H
depth_connected(c, H) = wet_connected(c, H) ? max(0, H - E(c)) : 0
```

地表面では海とつながらない窪地は `connected` では浸水させない。ただし、排水管の逆流による浸水は別経路で起こりうるため、`connected` の非浸水を「安全」と解釈してはならない。

### 4.3 仮想排水モデル

MVPでは流量、管径、ポンプ容量、集水区画、時間積分を扱わない。排水路の吐口を、潮位が上がると開放水面と同じ役割を持つ追加のseedとして扱う。

排水口 `o` は、護岸の海側にある「吐口」と、護岸の陸側にある「陸側端」のペアで表す。仮想敷高 `invert_mouth(o)` は海側の吐口に属するが、追加seedにするのは陸側端である。

シナリオの条件に応じたseedを次で定義する。

```text
seed_H = open_water_seed | (
  inland_node_mask & (invert_mouth <= H) & (gate_type == "none")
)
```

`gate_type = flap` の場合は、排水口の外側の潮位が敷高を超えても逆流を防ぐため、陸側端を追加seedにしない。`gate_type = none` の場合は、潮位が海側吐口の敷高を超えたときに管路を逆流して陸側端へ水が到達する仮定として追加seedにする。

既存の `compute_h_conn` と同じく、潮位を昇順に走査して各セルの最小到達水位 `h_conn_drainage` を求める。これにより、深さラスターを潮位ごとに焼かず、シナリオごとに1枚の到達水位ラスターだけを生成できる。

実装上は、既存の走査ループ内でS2だけ陸側端のseedを追加する。

```python
for h in np.arange(h_min, h_max + h_step / 2, h_step):
    seed_h = seed.copy()
    if scenario == "S2":
        seed_h |= inland_node_mask & (invert_mouth <= h)
    cand = passable & (e <= h)
    # seed_h と cand の連結成分から h_conn_drainage を更新する
```

S1は既存の `connected` とビット単位で同一のため、別の `h_conn_drainage_S1.tif` は生成しない。S2は潮位が海側吐口の敷高に達したときに、そのペアの陸側端を追加seedにする。どちらもseed集合と候補集合が `H` に対して単調増加するため、浸水セル集合も単調増加する。

このモデルは、排水量や水位の時間変化を再現するものではない。「その排水口を通じて潮位の影響が到達しうる範囲」を比較する閾値モデルである。

## 5. 仮想排水網データ

### 5.1 データ単位

GeoJSONまたはGeoPackageで、MVPでは次の1種類を持つ。

#### `synthetic_outfall_pairs`

| 属性 | 型 | 内容 |
|---|---|---|
| `id` | string | 仮想排水口ID |
| `geometry` | Point | 海側の吐口位置 |
| `inland_node` | Point | 陸側の端（集水桝・側溝の上流端） |
| `invert_mouth_m` | number | 海側吐口の仮想敷高 |
| `drain_to` | string | 排水先（海・河川・排水路など） |
| `gate_type` | string | `none` / `flap` |
| `source` | string | 常に `synthetic` |

### 5.2 仮想データ生成ルール

1. `scripts/87_bank_crest.py` が作る汀線直交断面と護岸天端
2. DEMから得た断面上の海側吐口・陸側端の標高
3. 既存の開放水面seed（`scripts/30_flood.py` の `find_open_water` が生成）
4. 既知の浸水履歴または現地情報（利用可能な場合）

基本ルールは以下とする。

- 護岸天端を挟んで、海側の吐口と陸側の端を1組のペアとして配置する。
- `geometry` は海側の口、`inland_node` は護岸内側の集水桝・側溝上流端を表す。
- 海側吐口の敷高は、陸側端の地盤高から一定の埋設深を引いて一意に決める。

  ```text
  invert_mouth_m = elevation(inland_node) - DRAINAGE_DROP_M
  DRAINAGE_DROP_M = 0.30m（既定値）
  ```

  `DRAINAGE_DROP_M` は `src/iwagaki/config.py` に置き、コードへ直書きしない。この値は実測管底高ではなく、側溝・管路が地盤面より下にあることを表す仮定である。負の標高になってもT.P.基準の値として保持し、0mに丸めない。
- 陸側端は、天端より内側のセルに置く。海側seedに置いてはならない。
- 排水先は既存seedまたは河川・海域を記録するが、MVPのseed判定には既存open-water seedを使う。
- 生成したペアは、実在施設ではなく「仮想の逆流経路」と表示する。

### 5.3 初期パラメータ

MVPの仮想排水口ペアは、海側吐口の位置、陸側端、上式から求めた海側吐口の敷高、排水先、逆流防止施設の有無だけを持つ。管径、流量、ポンプ容量、集水区画、管路勾配は将来の1D水理モデル用であり、今回の仕様には含めない。

排水口の敷高に幅を持たせる場合も、各ケースから `h_conn` を生成し、結果を「仮定別の件数」として集計する。

## 6. シナリオ

MVPは次の2シナリオに絞る。

| ID | 潮位 | 排水施設 | 目的 |
|---|---:|---|---|
| `S1` | 任意 | 既存の `connected` | 別ラスターを生成せず、既存レイヤをS1と呼ぶ |
| `S2` | 任意 | 吐口・陸側端ペア、フラップゲートなし | 潮位逆流の影響を比較する |

水位は固定値で焼き込まず、スライダが任意の `H` を評価できるようにする。`0.8m`, `0.9m`, `1.0m`, `1.2m` は確認用の代表値であり、行政の計画高潮位を意味しない。

## 7. 出力

### 7.1 ラスター

水位ごとの深さラスターは生成しない。水位に依存しない到達水位ラスターをシナリオごとに1枚だけ生成する。

- `h_conn_{condition}.tif`（既存）
- `h_conn_drainage_S2.tif`（S2用に1枚。S1は既存の`h_conn`を再利用）
- `h_conn_drainage_S2_invert_{minus,plus}_020.tif`（敷高の感度確認用。**配信しない**。§8）

敷高の感度確認は、件数ラスターを固定水位で焼かず、3ケースそれぞれの `h_conn` を保持する。

- `h_conn_drainage_S2_invert_minus_020.tif`
- `h_conn_drainage_S2.tif`（基準ケースを兼用し、複製しない）
- `h_conn_drainage_S2_invert_plus_020.tif`

**この3枚は配信しない。** 3ケースが実質同一であることが分かったため（§8）、
専用のRGBピラミッドは焼かない。画面に出す「仮定の段階」は既存の `diff_drainage`
タイルのR/G/Bをそのまま3段として読むので、配信物は増えない。

ビューアは `depth = max(0, H - E)` と `h_conn <= H` を使い、既存の水位スライダで任意の潮位を評価する。配信物の量は潮位の候補数に依存しない。

S1/S2の差分専用GeoTIFFは作らない。既存の差分タイル機構を再利用し、`scripts/80_build_web_tiles.py` の `DIFFS` に次を追加してRGBAタイルへ直接梱包する。

```python
"diff_drainage": ("h_conn_highres.tif", "h_conn_drainage_S2.tif")
```

チャネルは既存規則どおり、R=S1の到達水位、G=S2の到達水位、B=地盤高、A=255とする。

### 7.2 メタデータ

JSONに次を記録する。

- DEMファイル、解像度、標高基準
- 潮位の範囲・刻みと単位
- モデル種別
- 仮想データの生成方法
- 仮想排水口ペアの件数
- 海側吐口、陸側端、敷高、排水先、ゲート条件
- `DRAINAGE_DROP_M` と敷高補正値
- シナリオID
- 仮想データ使用フラグ
- 結果の注意書き

### 7.3 表示区分

地図では、少なくとも次を切り替えられるようにする。

- 単純モデル
- 地表連結モデル
- 仮想排水モデル
- ゲートなしとの差分
- 仮想敷高による仮定差
- 地盤高レイヤー

「浸水しない」と「計算対象外・未到達」は同じ色にしない。仮想排水モデルで排水された場所も、実際に安全であると断定せず、排水条件付きとして表示する。

## 8. 不確実性

**当初の軸（敷高 ±0.20 m）は効かないことが実測で分かった**（2026-08-27、東舞鶴）。
12 組の敷高は −0.30〜+0.30 m T.P. に収まっていて、±0.20 m ずらしても
**潮位 0.50 m 以上ではどのケースでも 12 組すべてが seed になる**。3 ケースで値が
違うセルは 9〜11 セル（0.0003 ha）だけで、既往最高潮位 0.93 m での浸水面積は
3 ケースとも 24.85 ha で一致した。**S2 の感度を支配しているのは敷高ではなく
吐口の有無である**（`docs/results.md`「仮想排水路を入れるとどうなるか」）。

敷高 3 ケースの計算は `scripts/31` に残す（`config.DRAINAGE_INVERT_CASES`）。
**この結論を再現するための感度確認であって、配信もしないし画面にも出さない。**

画面に出す 3 段は**モデルの入れ子**にする。

```text
S1（海から地表で連結） ⊆ S2（仮想排水路を逆流） ⊆ 潮位以下（地盤高 ≤ H）
```

入れ子が厳密に成り立つので、成立した段の数がそのまま**浸かると言うのにどこまで
仮定が要るか**になる。全セル・配信済みタイル 693 枚の両方で破れ 0 を確認した。

| 段 | 要る仮定 | 判定 |
|---|---|---|
| 3 | 無し | `h_conn(0.5m) <= H` |
| 2 | 吐口がある | `h_conn(S2) <= H` |
| 1 | 経路を示せない | `地盤高 <= H` だけ |

**§8 は当初「S1/S2 のゲート差はシナリオそのものなので不確実性の軸へ重複して
入れない」としていた。これを撤回する。** 重複を避けるための規定だったが、
唯一の代替軸（敷高）が退化していて、残る軸がこれしか無い。段は「確率」ではなく
**「どこまで踏み込んだ仮定が要るか」の梯子**として出すので、シナリオの再掲にはならない。

**確率ではない。** 段に重みは無く、段数を割った比率は出さない。
ファイル名・凡例・説明文に `probability` や「浸水確率」という語を使わない。

```text
assumption_steps(c, H) = count(h <= H for h in [h_conn_S1(c), h_conn_S2(c), elev(c)])
```

**配信物は 1 バイトも増えない。** 3 段はすべて既存の `diff_drainage` タイルに入っている
（R = `h_conn(0.5m)`、G = `h_conn(S2)`、B = 地盤高）。単純モデルでは「浸水し始める水位」が
そのまま地盤高なので、B も h_conn と同じ符号化・同じ比較で判定できる。

## 9. 検証

1. `simple` で地盤高0.8m・潮位0.9mのセルが0.1mになること。
2. `h_conn_drainage` を潮位昇順に計算したとき、浸水セル集合が減らないこと。
3. ゲートなしシナリオで、潮位が排水口敷高を超えたときに逆流影響が発生すること。
4. S1/S2の結果を任意の潮位でビューア上から評価できること。
5. S2を既往最高潮位 `H=0.93m` で評価した浸水面積 `A_S2` は、既存の連結浸水面積 `A_connected = 15.75ha` と単純モデルの面積 `A_simple = 15.75 + 10.57 = 26.32ha` の間に入ること。

   - `A_S2 ≈ 15.75ha`: 逆流経路が機能していない。陸側端が海側seed上、または護岸天端の外側にある可能性を疑う。
   - `15.75ha < A_S2 < 26.32ha`: 排水経路のある窪地だけが加わる期待どおりの状態。
   - `A_S2 ≈ 26.32ha`: 吐口ペアが多すぎ、S2が`simple`と実質同一になっている。配置密度を見直す。

   `26.32ha`への一致を合格条件にはしない。
6. 既存のハザードマップ、過去の浸水記録、現地写真と空間的に比較すること。京都府の高潮想定は堤防決壊前提であり、施設をゼロとする本モデルとの数値一致を検証根拠にしない。

実測データとの一致を主張できない場合は、精度指標を出さず、モデル間の差分と仮定を示す。

## 10. MVPの実装順序

### Phase 1: 既存モデル（完了）

- `simple` の潮位−地盤高
- 地盤高レイヤー
- `0.8m` と `0.9m` の比較
- `simple` / `connected` のparityテスト

### Phase 2: 仮想排水候補の生成

- `scripts/87_bank_crest.py` の断面から海側吐口・陸側端の候補を抽出する
- DEMから陸側端の地盤高を取得し、`invert_mouth_m = elevation(inland_node) - DRAINAGE_DROP_M` で敷高を生成する
- 既存のopen-water seedとの関係を検査する
- GeoJSONとして保存する

### Phase 3: S1/S2の到達水位

- ゲートあり・なしを切り替える
- `h_conn_drainage_S2.tif` を生成する（S1は既存`h_conn`を再利用）
- 既存の差分タイル機構に `diff_drainage` を追加する
- 既存の水位スライダで任意の潮位を評価する

### Phase 4: 仮定の段階（完了、2026-08-27）

- 排水口敷高の 3 ケースを計算した（`scripts/31`）→ **退化していた**（§8）
- 画面に出す 3 段はモデルの入れ子に置き換えた（`surface: 'assumption'`）
- 配信済みタイルを復号して解析ラスタとの一致を確認した（`docs/results.md`）
- 仮想モデルの注意書きを凡例に常時表示するようにした（§1 の必須表示）
- 描画の確認は `web/perf/assumshot.mjs`（GLSL は実行時にしか落ちない）

## 11. 今回は実装しないもの

- 実際の下水管径・マンホール・ポンプ操作の断定
- 波浪・越波・堤防決壊の動的計算
- 完全なSWMM＋2D水理モデル
- 行政の正式な計画高潮位の代替
- 流量・体積収支・浸水確率の統計的推定
- 仮想データを実在施設として地図に表示すること

## 12. 行政へのデータ整備提案との対応

本仕様で仮想値として置いているものを、行政から取得できれば実値に置き換えられる。

1. 排水口の位置、敷高、排水先、逆流防止施設の有無
2. ポンプ場の位置、容量、作動水位、運転ルール
3. 幹線雨水管・側溝・暗渠・集水桝の位置と管底高
4. 最新の航空レーザDEMと道路・護岸の標高
5. 過去の浸水地点、浸水位、発生時刻

行政向けには、仮想モデルと実測モデルを比較できる構造そのものを、データ整備の効果を示す成果物とする。
