## 0. 結論サマリ

- 吉原AOIについて、**PLATEAU（意味）** と **0.5m高解像度DEM（微地形）** は両方とも入手可能。**[実測]**
- **PLATEAU地形モデルは5m格子TIN**、京都府DEMは**0.5m格子** → **解像度差 10倍**。比較の前提は成立する。**[実測]**
- 京都府の**高潮浸水想定区域（水防法指定）は存在しない**。PLATEAUの舞鶴災害リスクモデルも 洪水(fld)・津波(tnm)・土砂(lsld) のみで **高潮(htd) は無い**。
  → 高潮水位は「指定ハザードの読み込み」ではなく**潮位統計を根拠にしたパラメータ H** として扱う。**[実測/既知]**
- 舞鶴の**公開 LAS/LAZ 点群は見つからなかった**。**[実測]** → 点群は別途提供予定。それまでは京都府0.5m DEMを高解像度地形の代替とする。

## 2. 高解像度地形：京都府「数値標高モデル（DEM）」

- カタログ: https://www.geospatial.jp/ckan/dataset/dem05_kyoto **[既知]**
- 提供: 京都府 農林水産部 林務課 **[既知]**
- 計測: 平成31（2019）〜令和5（2023）年の航空レーザ計測 **[既知]**
- 形式: **GeoTIFF, Float32, 0.5 m グリッド, nodata = -9999** **[実測: gdalinfo]**
- CRS: **EPSG:6674**（JGD2011 / 平面直角座標系 第VI系） **[実測]**
  - **[注意/実測]** GeoTIFFキーのCRS定義がEPSGレジストリと完全一致せずGDALが警告を出す。再投影時は `GTIFF_SRS_SOURCE=EPSG` の指定を推奨。
- 高さ: 標高（T.P.）。海面・水面はおおむね 0 付近、水域外周に nodata **[実測]**
- 1タイル = 2000 × 1500 px = **1000 m (E) × 750 m (N)**, 約 12 MB **[実測]**

### タイル命名（国土基本図図郭）の解読 **[実測: 実データのワールドファイルから導出・検証]**

`{系}{行}{列}{d1}{d2}{d3}{d4}` 例 `06LC9444`。

- `06` = 平面直角座標系 第VI系
- 2文字目 = 1/50000 図郭の行（南向き 30 km 刻み, `A`→ X最大）
- 3文字目 = 1/50000 図郭の列（東向き 40 km 刻み）
- 図郭 `06LC` の北西端 = **(E, N) = (-80000, -30000)**、`06MC` の北西端 = (-80000, -60000) **[実測: `06LC0011` の原点が (-80000,-30000)]**
- `d1` = 1/5000 図郭の行 (0-9, 3000 m 刻み)、`d2` = 列 (0-9, 4000 m 刻み)
- `d3` = 1/2500 象限 (2000×1500 m): 1=北西, 2=北東, 3=南西, 4=南東
- `d4` = 1/1000 象限 (1000×750 m): 1=北西, 2=北東, 3=南西, 4=南東

```
E0 = -80000 + d2*4000 + (2000 if d3 in {2,4} else 0) + (1000 if d4 in {2,4} else 0)
N0 = -30000 - d1*3000 - (1500 if d3 in {3,4} else 0) - (750 if d4 in {3,4} else 0)   # 06LC
```
（4タイルで検証済: `9621`,`8641`,`0011`,`9631` すべて一致）

### 内容の目視検証 **[実測]**

0.5m DEMをカラー段彩で描画した結果:
- 建物は**除去されている**（bare earth）。建物跡地に補間によるゴースト（わずかな平坦パッチ）が残る。
- 路地・道路・水路の護岸線・小段差が明瞭に読み取れる。
- 吉原入江・伊佐津川の水面は 0 付近でフラット。
- 集落部の地盤は概ね **0.5〜3 m T.P.**。

→ 高潮の連結性を左右する微地形（護岸天端、道路の微峰、路地の窪み）が実際に表現されている。

### 鉛直の刻みは図郭によって違う **[実測]**（2026-08-25）

**同じ「0.5m DEM」でも、タイルによって標高値の刻みが 0.1 m と 0.001 m に分かれる。**
「計測実施時期により精度が異なる場合がある」（下の利用規約の注記）が、
値そのものの量子化として現れている。

20 m 以下の標高値の一意な個数（AOI に掛かるタイルを全数で計測）:

| タイル | 一意な値 | 刻み | どの範囲で使う |
|---|---:|---|---|
| `06LC9441` / `9442` / `9444` / `06MC0421` | 11,838〜17,487 | **0.001 m** | 西舞鶴（海際の主要部） |
| `06LC8544` / `8634` / `8643` / `9522` / `9524` / `9542` / `9611`〜`9614` / `9621` / `9623` / `9631` / `9632` / `9641` | 86〜200 | **0.1 m** | **東舞鶴（16 枚すべて）** |
| `06LC9443` / `9531` / `9533` | 0〜206 | 0.1 m | 西舞鶴の山手 |

したがって**東舞鶴の「地盤高 0.80 m」はぴったり 0.8 である**（丸めた値であって
0.795〜0.805 の実測ではない）。画面で地盤高を読み上げる場面では押さえておく。

**浸水判定への影響は小さい。** 東舞鶴の護岸天端は 1.0〜1.3 m あり、
標高を一律 0.05 m 下げても潮位 0.9 m での浸水域は 1 ㎡も変わらない [実測]
（`docs/web_design.md`「窪地は『浸水しない』と同じ色で潰さない」）。
効くのは `h_conn` が 0.05 m 刻みなので、`float32` の 0.1 は
`0.30000001` のように表現されて 1 段ぶん（0.05 m）遅れて拾われることがある点だけ。

### 舞鶴 潮位観測所（気象庁, 記号 MZ） **[実測: 気象庁ページの数値]**

### 吉原入江の護岸天端高と越流開始水位 **[実測]**

外部資料（設計天端高）が見つからなかったので、**手持ちの 0.5m DEM から直接測った**
（`scripts/87_bank_crest.py`、出力 `data/out/bank_crest.json`）。

**越流開始水位** — `h_conn` の定義そのものを使う。
`h_conn(c)` は「海から c に至る経路上の最も低い峰」なので、
**護岸の内側（水際から 6 m より奥）の陸域における h_conn の最小値が、
その一帯を守っている護岸の最低天端高**にあたる。

| 地形 | 越流開始水位 [m T.P.] | 内陸 h_conn の p05 / p50 |
|---|---:|---|
| 高解像度 0.5m | **+0.25** | 0.85 / 1.25 |
| PLATEAU 5m | +0.40 | 0.75 / 1.20 |

**天端高の断面** — 水際から 6 m 以内の陸側セルを 20 m 角の区画に割り、
各区画の最大標高を天端高の代表値とした（311 区画）。

| 地形 | min | p05 | p50 | p95 | max |
|---|---:|---:|---:|---:|---:|
| 高解像度 0.5m | 0.20 | 0.80 | **1.20** | **2.15** | **3.50** |
| PLATEAU 5m | 0.30 | 0.69 | 1.10 | 1.76 | 2.41 |

**5m 地形は天端を削っている。** p95 で −0.39 m、最大で −1.09 m。
護岸は幅 1〜2 m の細い構造なので、5m 格子では隣の水面や低い地盤と平均されて
高い天端ほど低く出る。これは `docs/results.md` の「判定が変わる」現象の
直接的な物理的説明になっている。

**潮位との関係**（`§4` の基準値と突き合わせ）:

- 天端高の中央値 **1.20 m** は既往最高潮位 **0.93 m** より 0.27 m 高い。
- しかし p05 は **0.80 m**、最小は **0.20 m**。既往最高潮位は**低い所を確実に越える**。
- 越流開始水位 **0.25 m** は朔望平均満潮位 **0.44 m** より低い。
  つまり **大潮の満潮では既に内陸まで水がつながる経路がある**。

吉原は漁村で舟の出入りがあり、連続した高い防潮堤ではなく所々で水面に接している。
上の数字はその地形をそのまま反映している。

**注意**
- 設計天端高との突き合わせはしていない。DEM から測った**現況の高さ**である。
- 京都府 DEM は森林資源把握が目的の成果で、市街地の精度は保証されていない。
- **水門・樋門は入江に無い**（照会で確認）。閉鎖による過大評価の心配は無い。
  **ただし誤差の向きが逆に効く要因が残る。** 排水路の吐口に
  **フラップゲートが設置されていない**ので、潮位が上がれば**吐口から逆流しうる**。
  本モデルは地表面の連結性しか見ておらず**管路を経路に含めていない**ため、
  内陸側の浸水を**過小に**評価している可能性がある。吐口の位置と敷高が要る。

## 標高成果の世代 **[未確認]**

**指摘:** 3D 都市モデルと点群は**現在の新しい標高成果ではなく旧標高成果**で
作られているが、整合は問題ないか。

**論点は正しい。** 本リポジトリが使っているジオイドは
`PROJ EPSG:6697 -> EPSG:4979` 経由の **GSIGEO2011**（AOI 中心で N = 36.955 m、
`catalog.json` の `vertical.geoid_source`）で、これは**旧成果側のモデル**である。

### 効くところと効かないところを分ける

| | 世代のずれが効くか |
|---|---|
| **条件間の差**（`baseline` vs `highres` vs `control` vs `pointcloud`） | **効かない。** 全条件が同じ基準に乗っていれば差し引きで消える。**これが本リポジトリの成果物である** |
| **絶対値の T.P.**（地盤高、`h_conn` の水位そのもの） | **効く。** 潮位・計画高潮位と突き合わせる場面では世代を揃える必要がある |
| **3D Tiles の重ね合わせ**（楕円体高 ↔ T.P.） | 効くが**表示だけ**。ずれても解析値は動かない |

### 揃っている根拠 **[実測]**

**入力どうしは実測で合っている。** 航空レーザ DEM（2019-2023）と
地上 SLAM（2026-07）の鉛直差は **中央値 +0.002 m / MAD 0.069 m**
（`docs/results.md`「鉛直基準は一致している」）。**7 mm** は世代差として
説明できる量ではないので、**この 2 つは同じ実現値に乗っている**と見てよい。

**PLATEAU の測量年は 2024 年である** [実測]。配布 CityGML の
`uro:surveyYear` が建物 1,513 件すべてで **2024**（`53351246_bldg_6697_op.gml`）。
改定の施行は 2025-04-01 なので**それより前**で、下記の教示と整合する。
なお `dem` メンバーには `surveyYear` が無く、`uro:thematicSrcDesc = 022` だけを持つ。
**コードリスト（`DataQualityAttribute_thematicSrcDesc.xml`）が手元の配布物に無いため
値の意味は未確認** [未確認]。次に配布 zip を取るときは `codelists/` を残すこと。

**PLATEAU も点群も旧成果である** [既知]。指摘者（点群の提供元）から
「3D 都市モデルと点群データは新しい標高成果ではなく**旧標高成果**で作成している」
と教示された（2026-08）。本リポジトリのジオイドも旧成果側なので、
**4 条件はすべて同じ世代で揃っている。**

**残るのは潮位側である** [未確認]。浸水の判定は地盤高と潮位を突き合わせて出すので、
**気象庁の潮位から換算した T.P. 値がどの世代の基準によるものか**を揃える必要がある。
「条件間の差だから世代は効かない」で済まないのはここで、
**絶対値の比較は今まさに行われている**。当地の標高が新成果で改定されていれば、
その分だけ判定の絶対値がずれる。改定量が分かれば差し引いて影響を出せる。

### 改定そのものの事実 **[既知: 国土地理院]**（2026-08-24 調査）

| | |
|---|---|
| 呼び方 | 改定前 **測地成果2011** → 改定後 **測地成果2024** |
| 施行 | **令和 7 年（2025）4 月 1 日** |
| 理由 | 従来は日本水準原点からの水準測量で決めており、**原点から離れるほど誤差が累積**していた。改定後は衛星測位を基盤にする |
| 最大改定量（三角点） | 宮城県牡鹿半島 **+57 cm** / 北海道知床半島 **−67 cm** |
| 最大改定量（水準点） | 宮城県牡鹿半島 **+23 cm** / 北海道別海町 **−40 cm** |
| 任意地点の改定量 | 補正パラメータで求める。**三角点用と水準点用で別物**。コンター図は 5 cm 間隔 |

**舞鶴の改定量は約 −15 cm** [仮説]（2026-08-24 調査）。国土地理院
「地域別の標高改定量（試算）」の**中部・近畿地方の面**（緯度経度の目盛りあり）で、
舞鶴（135.3°E / 35.5°N）は **−15 と −20 の等値線の間**にある。
等値線間隔は 5 cm なので **−15 ± 5 cm**。水準点標高補正パラメータのコンター図でも
同じ色帯だが、近傍に数値ラベルが無いため読み値は取れていない。
**国土地理院自身が「試算値のため実際の改定量とは異なります」と付記している**ので
[仮説] 止まり。確定値は補正パラメータを引く必要がある。

**これは無視できない大きさである。** 本解析が「差が出た」と扱う閾値は 0.25 m で、
**15 cm はその 6 割**にあたる。潮位が 15 cm ずれれば `H = 0.68 m` での判定は大きく動く。
「数 cm なら結論は動かない」という見立ては**取り下げる**。

### 直し方の見通し（記録）

**安いのは潮位側を 2011 に戻すこと。** 地形は 4 条件のラスタとタイル
（8 ピラミッド・1,048 枚）と `h_conn` を作り直すことになるが、潮位は定数 3 つと
参照潮位 6 件である。改定量 δ が確定すれば
`潮位表基準面の標高(2011) = -0.066 - δ` として換算し直せる。

**向きの試算。** 改定量が δ ≈ −0.15 m（2024 の標高が 2011 より低い）なら、
同じ物理的な海面を 2011 の T.P. で表すと **0.15 m 高くなる**。我々は 2024 の潮位を
2011 の地形にぶつけているので、**水位を 0.15 m 低く見ている = 浸水を過小に
評価している**ことになる。

**ただしこれは実測の突き合わせと逆を向く。** `docs/results.md`
「実際の被害記録との突き合わせ」では、モデルの件数は実測より**多め**に出ている。
補正するとさらに多くなる。**この不整合は未解決** [未確認] で、
(a) 調査は申告・目視で確認できた家屋だけなので実測値は下限にすぎない、
(b) 上の −15 cm は試算値をコンター図から読んだもので、水準点用の確定値ではない、
のどちらか（または両方）だと見ている。**確定値を引くまで補正は入れない。**
