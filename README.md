# iwagaki

舞鶴市 **吉原**地区を対象に、**同じ高潮水位に対して、地形データを変えると浸水判定が
どこで変わるか**を地物単位で示すプロトタイプ。

公開 viewer: **https://iwagaki-viewer.tonbo.workers.dev**

![H=1.0m での比較](docs/images/flood_compare_H1.0.png)

左 = PLATEAU 5m 地形の浸水域、中 = 0.5m 航空レーザ地形の浸水域、
右 = 差分（赤 = 新たに浸水 / 黄 = 浸水しなくなる）。

---

## 概要

PLATEAU と地形観測を「3D で重ねて見せる」のではなく、**役割を分けて突き合わせる**。

| 役割 | データ | 担うもの |
|---|---|---|
| semantic city model | PLATEAU（建物・道路） | 地物の**識別子と意味** |
| terrain observation | 0.5m 航空レーザ DEM / 地上点群 | **現況の微地形** |
| derived assertion | 本リポジトリの解析結果 | 地物ごとの地盤高・浸水深・**判定の変化** |

出力は「浸水ハザードマップ」ではない。**「地形データを変えると、どの道路・どの建物で
判定がひっくり返るか」**という差分そのものが成果物である。

### 使っているデータ

| データ | 中身 | 規模 | 用途 |
|---|---|---|---|
| PLATEAU 建物 LOD1 | CityGML `bldg` | AOI 内 **930 棟** | 地物の識別子・用途/構造の属性・3D Tiles での表示 |
| PLATEAU 道路 | CityGML `tran` | AOI 内 **293 本** | 地物の識別子・区間種別（橋梁/高架/トンネルの除外に使う） |
| PLATEAU 地形 LOD1 TIN | CityGML `dem` 2 メンバー | 5 m 格子相当 | **`baseline` 地形** |
| 京都府 数値標高モデル | 航空レーザ DTM、図郭 zip から 4 タイル | **0.5 m 格子** | **`highres` 地形**、`control`（5 m に集約） |
| 地上点群 | LAS 1.4 / PDRF 7、バックパック SLAM 10 ファイル | **20.0 GB / 5.56 億点** | **`pointcloud` 地形**（地表面を融合）と表示用 COPC |
| 気象庁 潮位 | 舞鶴の推算潮位表（毎時）と観測基準面 | 1 年分 | 水位スライダの参照水位、潮位基準面 → T.P. の換算 |
| ジオイド GSIGEO2011 | PROJ network 経由 | AOI で N = 36.955 m | 3D Tiles の楕円体高 ↔ 標高（T.P.）の換算 |

地上点群は 20 GB あるが、**AOI に入るのは 4.37 億点で、地表面として使えるのは
3.17 ha 分だけ**である（バックパック SLAM は歩いた線に沿った帯しか取れない）。
AOI 100 ha に対する被覆は 7.88 %。詳細は `docs/data.md`。

### 比較する 4 つの地形条件

| 条件 | 中身 | 切り分けたいもの |
|---|---|---|
| `baseline` | PLATEAU 地形モデル LOD1 TIN（5 m 格子） | 出発点 |
| `highres` | 京都府 数値標高モデル 0.5 m（航空レーザ 2019-2023） | データ源 + 解像度の合計 |
| `control` | `highres` を 5 m に平均集約 | **解像度だけ**を落とした対照 |
| `pointcloud` | `highres` に地上点群（バックパック SLAM 2026-07）の地表面を融合 | 地上観測が足す分 |

`control` があるので「データ源が効いたのか、解像度が効いたのか」を分けられる。

### 連結浸水開始水位 `h_conn`

浸水判定を `標高 < 水位` では行わない。**海から連結して到達できるか**を解く。

各セルについて「そのセルが海と連結して浸水し始める最小水位」`h_conn` を 1 度だけ計算する。
すると任意の水位 H について

- 浸水するか = `h_conn ≤ H`
- 浸水深 = `max(0, H − 標高)`

が定数時間で決まる。**水位を動かしてもサーバ往復も再計算も発生しない。**
viewer の水位スライダはこの性質の上に載っている。

モデルは静水位（hydrologically-connected bathtub, Poulter & Halpin 2008 系）で、
越流の時間発展・流量・波の打ち上げは含まない。詳細は `docs/design.md`。

## viewer で何ができるか

公開先は **https://iwagaki-viewer.tonbo.workers.dev**。

| | |
|---|---|
| 対象範囲 | 吉原（100 ha・4 条件・点群あり）／西舞鶴（625 ha）／東舞鶴（**1,000 ha**）。広い 2 つは **0.5m DEM と PLATEAU 5m だけ** |
| 地形データ | その範囲が配信している条件を切り替える。並びは作られ方の順（源を替える → 解像度を上げる → 観測を足す） |
| 判定差 | 選んだ条件に至る 1 段の差を面で塗る。`5m 対照` なら**データ源だけ**の差 |
| 潮位 | 0.00〜3.00 m T.P. を 0.05 m 刻みで動かす。**サーバ往復も再計算も起きない**（`h_conn` から即算） |
| 水面 | 潮位の高さに**水平な水面**を張る。同じタイルを 2 回描くだけなので配信物は増えない |
| 窪地 | **標高は潮位より低いが、地表面をたどると海に出ない土地**を斜線で出す。排水路の吐口にフラップゲートが無いので実際には逆流しうる（`docs/design.md`「既知の限界」2）。**判定には混ぜない。** 標高と `h_conn` は同じ画素にあるので配信物は増えない |
| 建物の色 | 用途で塗るか、**浸水深（床下 / 床上 0.50 m）**で塗るか。潮位を動かしても b3dm は作り直さない |
| 道路 | PLATEAU の道路 293 本。浸かると**通行支障クラス**（0.1 / 0.3 / 0.5 m）で塗る |
| 絞り込み | 判定が変わる地物だけを残す |
| 地物のクリック | その条件の地盤高・`h_conn`・浸水深・通行と、基準との差 |
| 断面 | 2 点クリックで測線を引く。**4 条件を線で重ねられる唯一の場所** |
| 点群 | バックパック SLAM の実測色で出す。**表示専用**（浸水解析には融合した地形ラスタを使う） |

設計は `docs/web_design.md`、配信性能の実測は `docs/web_results.md`。

数字は `scripts/` の番号。実行手順は `docs/usage.md`。

**`h_conn` を持つことが全体の設計を決めている。** 水位ごとに浸水域を焼くのではなく
「そのセルが浸水し始める水位」を 1 枚持つので、配信物は水位の数に依らず一定で、
ブラウザ側は水位が変わってもサーバに問い合わせない。

## 対象範囲

**3 つある。** 主張（地形データを変えると判定がどう変わるか）を担うのは吉原で、
あとの 2 つは市の要望（2026-08）で足した**浸水範囲の面的表示**用である。

| 範囲 | 広さ | 地形条件 | 地物 | 何のためか |
|---|---:|---|---:|---|
| **吉原** `yoshiwara` | 100 ha | 4 条件（地上点群あり） | 1,223 | **判定の変化そのもの**。README / `docs/results.md` の数字はすべてこの範囲 |
| **西舞鶴** `nishi_maizuru` | 625 ha | 0.5m ＋ PLATEAU 5m ＋ 判定差 | 6,118 | 面的表示。吉原を含む |
| **東舞鶴** `higashi_maizuru` | **1,000 ha** | 同左 | 8,368 | 面的表示。市の依頼で東を JR 小浜線まで広げた（2026-08） |

広い 2 つに点群は無い（バックパック SLAM を歩かせたのは吉原だけ）。
切り替えは viewer の「対象範囲」、解析は `IWAGAKI_AOI`（`docs/usage.md`）。

### 吉原（主対象）

舞鶴市 吉原（東吉原・西吉原、吉原入江周辺）。

| 項目 | 値 |
|---|---|
| AOI | EPSG:6674（JGD2011 / 平面直角座標系 第VI系）で X −61500〜−60500, Y −60500〜−59500 |
| 大きさ | **1000 m × 1000 m** |
| 中心 | 東経 135.32796°, 北緯 35.45731° |
| 標高（0.5m DEM） | 0.00 〜 152.17 m T.P.（中央値 1.80 m） |
| 陸域 / 開放水面 | 702,033 m² / 297,968 m² |
| PLATEAU 地物 | 1,223 件（建物 930 / 道路 293。うち橋梁・高架など 6 件は地盤高が意味を持たないため解析対象外） |

吉原は二本の水路（吉原入江・伊佐津川）に挟まれた低平な砂州上の漁村集落で、
市街地部の標高は概ね 0.5〜3 m T.P. しかない。
**護岸天端・道路の微かな峰・路地の窪みが浸水の連結性を支配する**地形であり、
5 m 格子ではそれらが平滑化される。微地形が効くことを期待できる典型として選んだ。

### 面的表示用の 2 範囲

| 項目 | 西舞鶴 | 東舞鶴 |
|---|---|---|
| AOI（EPSG:6674） | X −62000〜−59500, Y −61250〜−58750 | X −57000〜**−53000**, Y −58750〜−56250 |
| 大きさ | 2500 m × 2500 m | **4000 m × 2500 m** |
| 陸域 / 開放水面 | 476.4 ha / 148.6 ha | 761.6 ha / 238.4 ha |
| 標高（0.5m DEM） | 0.00 〜 302.75 m（中央値 16.5 m） | 0.00 〜 285.60 m（中央値 10.2 m） |
| PLATEAU 地物 | 6,118（建物 4,563 / 道路 1,555） | 8,368（建物 6,308 / 道路 2,060） |
| 配信タイル | 634 枚 × 3 = 28.8 MB | 960 枚 × 3 = 28.9 MB |
| 3D Tiles | 46 b3dm / 11.7 MB（LOD1） | 76 b3dm / 16.0 MB（LOD1） |

矩形は市の資料（`高潮表示範囲.pdf` の 2 つの〇）より余裕を持たせ、
**開放水面（湾）を必ず含める**ようにした。`h_conn` の seed は
「配列の外周に接する低い連結成分」なので、海を切り落とすと浸水がどこからも始まらない。

**東舞鶴は 2026-08-25 に東へ 1.5 km 広げた**（625 → 1,000 ha）。市から
「表示範囲の東側を JR 線路まで」と赤破線入りの地図で依頼があったため。
破線は総括図を GSI 標準地図に海岸線で合わせて座標に起こし、**JR 小浜線の上に
乗る**ことを確認した（残差 ±60 m）。東端は破線ではなく**低地が尽きる位置**で
決めている（`src/iwagaki/config.py`）。

## リポジトリ構成

```
src/iwagaki/     解析ライブラリ（`versioning.py` = 配信物の URL に内容ハッシュ）
scripts/         前処理パイプライン（番号順に実行）
data/            raw / interim / out（すべて git 管理外）
web/
  src/domain/    純ロジック（描画ライブラリに依存しない）
  src/net/       リクエストスケジューラ（優先度・帯域・キャンセル・coalescing）
  src/pointcloud/ COPC index / LOD / decode / renderer
  src/three/     Viewer（カメラ・投影）と地形 / PLATEAU / 地物 / 点群のメッシュ
  src/view/      カメラのプリセット、ビューキューブ、測線
  src/ui/        操作パネル / インスペクタ / 断面図 / 計測パネル
  perf/          実測ハーネス（ネットワークプロファイル別 / A-B / 診断）
  test/          純関数の単体テスト
  deploy/        Cloudflare 配信
```
